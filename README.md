# راهنمای کامل — Tradeiscool (نسخه‌ی نهایی فعلی)

دو ربات مستقل، هر دو به‌صورت **پیوسته** (نه فقط دوره‌ای) روی GitHub Actions اجرا می‌شوند و هر ۵ ساعت خودشون رو با یک اجرای تازه‌ی از-قبل-صف‌شده جایگزین می‌کنن تا هیچ‌وقت خاموش نباشن:

| فایل | کار | فناوری کلیدی |
|---|---|---|
| `candle_engine.py` | سیگنال بیت‌کوین/اتریوم (۶ تایم‌فریم) + گزارش روزانه + سیگنال دستی ادمین | Binance Futures WebSocket (اصلی) + Coinbase (پشتیبان) برای دقت چند ثانیه‌ای استاپ/تارگت |
| `subscription_bot.py` | پلن‌ها، پرداخت تتر، تخفیف، رفرال، عکس‌سود، تعمیر/توقف، پشتیبانی | Long-polling ۵ ثانیه‌ای برای پاسخ‌دهی آنی |

## این نسخه چه چیزهایی رو اصلاح کرد

1. **تشخیص سیگنال فوروارد‌شده، بر اساس محتوا نه متادیتا**: قبلاً فقط پیام‌هایی که تلگرام متادیتای «فوروارد» روشون گذاشته بود بررسی می‌شدن. حالا هر پیامی که مستقیم توی کانال با همون ایموجی لانگ (🟢) یا شورت (🔴) شروع بشه - فوروارد شده باشه یا مستقیم تایپ/پیست‌شده - و ساختار Entry:/Stop: رو داشته باشه، خودکار به‌عنوان یکی از سیگنال‌های ربات شناخته می‌شه (این کار برخی فوروارد‌هایی که به‌خاطر تنظیمات «محافظت از محتوا» متادیتای فوروارد نداشتن رو هم پوشش می‌ده).
2. **برچسب اشتباه سیگنال‌های دستی/فوروارد**: هم در پیام‌های کانال، هم در گزارش روزانه، هم در `/results` — دیگه با برچسب عمومی «Manual» نشون داده/شمارش نمی‌شن؛ دقیقاً با نام خودِ ارز واقعی (BTC یا ETH)، مثل بقیه‌ی سیگنال‌ها. جدول «By timeframe» در `/results` هم دیگه یک ردیف جعلی «manual» نشون نمی‌ده (چون این سیگنال‌ها واقعاً تایم‌فریم ندارن)؛ همچنان کامل توی جمع کل و توی «By symbol» حساب می‌شن.
3. **تاخیر سیگنال‌های 1m/5m که باعث می‌شد تارگت تقریباً بلافاصله بعد از ورود پست بشه**: چون این دو تایم‌فریم به‌خاطر محدودیت بودجه‌ی Twelve Data هر ۱۰-۱۵ دقیقه یک‌بار چک می‌شن، وقتی چند کندل بسته‌شده یک‌جا می‌رسیدن، اگه سیگنال روی یکی از کندل‌های قدیمی‌تر آن دسته پیدا می‌شد، بلافاصله باز می‌شد و در همون حلقه با کندل‌های بعدی (که در واقعیت خودشون هم قبلاً بسته شده بودن) فوراً به تارگت/استاپ می‌خورد. حالا فقط سیگنالِ روی نزدیک‌ترین کندل به «الان» باز می‌شه؛ کندل‌های قدیمی‌تر همون دسته فقط برای به‌روزرسانی اندیکاتور/معامله‌ی باز پردازش می‌شن.
4. **تناقض هم‌زمان BUY/SELL** (نسخه‌ی قبل): سیگنال دستی/فوروارد جدید مخالف‌جهت، اول سیگنال باز قبلی روی همون ارز رو رسماً می‌بندد.
5. **انتشار تضمینی نتیجه‌ی هر سیگنال**: تا ۳ بار retry برای ارسال پیام نتیجه + `log_trade_result` (که سیگنال رو وارد محاسبات/`/results` می‌کنه) همیشه بلافاصله بعد از بسته‌شدن معامله اجرا می‌شه، صرف‌نظر از موفقیت ارسال پیام تلگرام.
6. **گزارش روزانه‌ی تکراری**: پرچم «امروز فرستاده شد» با الگوی mark-then-send در یک فایل جدا ثبت می‌شه.
7. **تاخیر در به‌روزرسانی نتایج**: هر دو اسکریپت حالا هر ۲ دقیقه `git pull` می‌کنن، صرف‌نظر از این‌که خودشون تغییر محلی داشته باشن یا نه (قبلاً فقط شرطی pull می‌کردن).
8. **چارت لحظه‌ی استاپ/تارگت**: یک دور کندل تازه از بازار گرفته می‌شه، نه یک نقطه‌ی «Live» روی چارت قدیمی.
9. **منبع قیمت زنده و محافظ استاپ کاذب**: منبع اصلی Binance Futures (mark price) با fallback خودکار به Coinbase؛ برخورد به استاپ نیاز به تایید در تیک دوم داره.
10. **مدیریت ریسک و سرمایه برای کاربران**: در `/disclaimer` — حداکثر ۳ تا ۵ درصد مارجین حساب در هر معامله، فرمول انتخاب اهرم، تاکید بر عدم ورود با کل سرمایه.

⚠️ **این ریپو باید Public باشد** (نه Private) — چون هر دو اسکریپت ساعت‌ها پیوسته اجرا می‌شن، دقیقه‌های Actions روی ریپوی Private به‌سرعت تموم می‌شه؛ روی ریپوی Public نامحدود و رایگانه. Secret ها حتی روی ریپوی Public کاملاً محرمانه می‌مونن.

## بخش اول: پیش‌نیازها

1. ریپوی گیت‌هاب **Public**
2. ربات تلگرام (از `@BotFather`)
3. کانال تلگرام خصوصی برای مشترکین + (اختیاری) یک کانال عمومی تیزر
4. کلید رایگان از **twelvedata.com** (برای سیگنال‌های کندلی و طلا حذف‌شده... فقط بیت‌کوین/اتریوم)
5. آدرس کیف‌پول ترون (TRC20) + (اختیاری) BNB Chain (BEP20)
6. آیدی عددی همه‌ی ادمین‌ها از `@userinfobot`

## بخش دوم: تنظیم کانال و ریپو

1. کانال خصوصی بسازید → ربات رو ادمین کنید با دسترسی `Invite Users via Link` و `Ban Users`
2. `chat.id` کانال رو با فوروارد یک پیام به `@RawDataBot` بگیرید
3. ریپو رو **Public** کنید (Settings → Danger Zone → Change visibility)
4. همه‌ی فایل‌های این پکیج رو آپلود کنید

### Secrets (Settings → Secrets and variables → Actions)

| Secret | مقدار | اجباری؟ |
|---|---|---|
| `BOT_TOKEN` | توکن ربات | ✅ |
| `PRIVATE_CHANNEL_ID` | آیدی کانال خصوصی | ✅ |
| `TWELVEDATA_API_KEY` | کلید Twelve Data | ✅ |
| `WALLET_ADDRESS_TRC20` | آدرس کیف‌پول ترون | ✅ |
| `ADMIN_USER_IDS` | آیدی‌های عددی ادمین‌ها، با کاما جدا | توصیه‌شده |
| `PUBLIC_CHANNEL_LINK` | لینک کانال عمومی تیزر | اختیاری |
| `WALLET_ADDRESS_BEP20` / `BSCSCAN_API_KEY` | برای فعال‌کردن پرداخت BEP20 | اختیاری |
| `SUPPORT_CONTACT` | مثلاً `@your_support_username` | اختیاری |
| `PAYMENT_WINDOW_MINUTES` | پیش‌فرض ۴۵ | خیر |
| `REFERRAL_REWARD_DAYS` | پیش‌فرض ۷ | خیر |
| `PHOTO_REWARD_DAYS` / `MAX_PHOTO_REWARDS_PER_MONTH` | پیش‌فرض ۱ روز / ۵ بار در ماه | خیر |
| `DAILY_REPORT_HOUR_UTC` | ساعت ارسال گزارش روزانه (پیش‌فرض ۲۱ UTC) | خیر |

5. تب **Actions** → هر دو ورک‌فلو رو فعال کنید، بعد **Run workflow** رو دستی بزنید تا زودتر از کرون شروع بشن

## بخش سوم: منطق سیگنال (وضعیت فعلی)

**نمادها:** فقط BTC/USD و ETH/USD (طلا طبق تصمیم شما حذف شد)
**تایم‌فریم‌ها:** 1m، 5m، 15m، 1h، 4h، 1d

### فیلترهای ورود (برای کاهش سیگنال کاذب در بازار رنج)
- هم‌راستایی با EMA7/EMA25 + شکل کندل خاص (shadow ratio)
- **ADX ≥ ۲۰** (قدرت روند) - اگه بازار رنج/بی‌روند باشه، سیگنال صادر نمی‌شه
- **الگوی تاییدشده اجباری** - باید واقعاً یک اینگولفینگ یا پین‌بار مشخص رخ داده باشه (نه فقط شکل کلی کندل)

### مدیریت پوزیشن
| تارگت | R | عملیات |
|---|---|---|
| Target 1 | 1R | بستن ۵۰٪ پوزیشن |
| Target 2 | 2R | بستن ۵۰٪ باقی‌مانده + ریسک‌فری (استاپ به نقطه ورود) |
| Target 3 | 3R | بستن ۷۰٪ باقی‌مانده + شروع تریلینگ‌استاپ |
| Target 4 | 4R | بستن ۸۵٪ باقی‌مانده + ۱۵٪ («Runner») با تریلینگ باز می‌مونه، بدون سقف |

حد ضرر اولیه = فاصله‌ی محافظه‌کارانه‌تر از (EMA7 کندل سیگنال) یا (آخرین سوینگ لو/های ۱۰ کندلی)، به‌علاوه بافر ۰.۷۵ برابر ATR.

### دقت زمانی
- **بیت‌کوین/اتریوم:** یک اتصال WebSocket زنده به Coinbase مدام باز می‌مونه؛ استاپ/تارگت با تاخیر چند ثانیه‌ای شناسایی می‌شه (نه بسته‌شدن کندل)
- قیمت «Entry» نمایش‌داده‌شده هم از یک کوئری قیمت زنده در لحظه‌ی انتشار گرفته می‌شه، نه از کندل بسته‌شده

⚠️ اتصال واقعی WebSocket رو از لاگ Actions (دنبال `🔌 WebSocket connected`) تایید کنید؛ اگه قطع بود، رهگیری REST هر ۱۵ دقیقه به‌عنوان پشتیبان کار می‌کنه.

## بخش چهارم: سیگنال دستی ادمین

دو راه برای ثبت یک سیگنال دستی هست — هر دو دقیقاً یک نتیجه دارن (پست با فرمت استاندارد + استاپ + ۴ تارگت + چارت، رهگیری زنده توسط WebSocket/REST، و شمارش در `/results`):

**۱) دستور در چت خصوصی با ربات:**
```
/admin_manual_signal BTC/USD BUY 65000 64000
```

**۲) پست/فوروارد مستقیم در خود کانال — دو حالت:**

- **فوروارد یا پست مستقیم (خودکار، بدون نیاز به تگ):** هر پیامی که مستقیم توی کانال با همون ایموجی لانگ (🟢) یا شورت (🔴) شروع بشه - فوروارد شده باشه یا مستقیم تایپ/پیست‌شده - و ساختار Entry:/Stop: رو داشته باشه، خودکار به‌عنوان یکی از سیگنال‌های ربات شناخته و صف می‌شه. تشخیص بر اساس ظاهر متن است، نه متادیتای «فوروارد» تلگرام - چون بعضی فوروارد‌ها (مثلاً از کانالی با «محافظت از محتوا») اون متادیتا رو ندارن. اگه با این ایموجی شروع بشه ولی Entry:/Stop: پیدا نشه، یا سیگنال تکراری باشه، ربات با یک پیام کوتاه اطلاع می‌ده که رد شد.
- **تایپ دستی با تگ:** اگه منبع فرمت متفاوتی داره یا می‌خواید دستی بنویسید:
```
#signal BTC/USD BUY 65000 64000
```

در هر دو حالت، ربات زیر همون پیام یک تاییدیه («📌 Manual signal queued...» یا «🔎 Detected as a forwarded signal...») یا در صورت مبهم‌بودن فرمت تگ، یک پیام خطا با فرمت درست می‌فرسته.

⚠️ **قبلاً**: هر سیگنالی که مستقیم توی کانال پست/فوروارد می‌شد اصلاً دیده نمی‌شد، چون `subscription_bot.py` فقط پیام‌های چت خصوصی/گروه (`message`) رو می‌خوند و آپدیت‌های نوع پست کانال (`channel_post`) رو کلاً نادیده می‌گرفت. همین باعث می‌شد نه پیام حدضرر/تارگت براش ارسال بشه، نه نتیجه‌ش در `/results` حساب بشه. با اضافه‌شدن دو مسیرِ بالا، این مشکل حل شده.

فاصله‌ی زمانی تا پست نهایی در کانال (چه از دستور، چه از تگ کانال): چند دقیقه، تا اجرای بعدی دور اسکن `candle_engine.py`.

## بخش پنجم: گزارش روزانه‌ی خودکار

هر روز بعد از ساعت `DAILY_REPORT_HOUR_UTC` (پیش‌فرض ۲۱:۰۰ UTC)، خلاصه‌ی همه‌ی سیگنال‌های بسته‌شده‌ی همون روز (با جزئیات هر معامله: نماد، تایم‌فریم، نتیجه، R) مستقیماً در کانال پست می‌شه — حتی روزهایی که هیچ سیگنالی بسته نشده («No signals closed today»)، برای شفافیت و نشون‌دادن این‌که سیستم فعاله.

- **تمدید/لغو/کد تخفیف/رفرال** — از طریق `/plans`, `/code`, `/refer`
- **پاداش عکس سود** — کاربر عکس می‌فرسته، ادمین تایید/رد می‌کنه، `/admin_photos` برای گرفتن دوباره‌شون
- **تعمیر/توقف** — `/admin_pause` و `/admin_resume` (با تمدید خودکار مدت توقف)

- **آمار عملکرد** — `/results` (تفکیک نماد/تایم‌فریم) و `/pnl AMOUNT`

لیست کامل دستورات ادمین: `/admin_help`

## عیب‌یابی سریع

- **سیگنال یا پیام دیر می‌رسه:** چک کنید هر دو ورک‌فلو واقعاً «فعال» هستن (نه Cancelled/Failed در تب Actions) و لاگ رو برای خطای مشخص بخونید
- **WebSocket وصل نمی‌شه:** رهگیری REST همچنان کار می‌کنه، فقط کندتر؛ اگه دائم قطعه، لاگ خطا رو برام بفرستید
- **`/admin_*` جواب نمی‌ده:** آیدی عددی رو در `ADMIN_USER_IDS` دوباره چک کنید (با کاما، بدون فاصله‌ی اضافه)
- **پرداخت شناسایی نمی‌شه:** مبلغ باید دقیقاً (تا ۲ رقم اعشار) و روی شبکه‌ی درست باشه
